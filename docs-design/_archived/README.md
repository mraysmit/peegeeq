# PeeGeeQ Documentation Archive

**Status:** HISTORICAL AND SUPERSEDED MATERIAL — NOT A CURRENT PRODUCT CONTRACT

This directory preserves documentation that remains useful as design history, implementation
evidence, investigation context, or project-governance history. For current behavior, begin with
the [maintained documentation index](../../docs/README.md). For incomplete work and accepted
verification evidence, use the [consolidated task register](../tasks/tasks.md).

## Archive organization

- `completed-records/` — completed implementation plans, reviews, and rollout records.
- `historical-evidence/` — dated test results, investigations, and validation snapshots.
- `internal-notes/` — internal process material that is not product documentation.
- `superseded-guides/` — guides replaced by a maintained authority elsewhere.
- `governance/` — completed documentation-control and migration records.
- The files directly under `_archived/` are earlier historical records retained before the
  categorized archive structure was introduced.

## Preservation rules

- Archived source content is retained byte-for-byte when moved.
- A status written inside an archived document describes its original reviewed revision; the
  archive location takes precedence when deciding whether it is current guidance.
- Broken relative links inside immutable historical records may reflect their original location.
  Current guides and indexes must use valid links to the archived destination.
- An archived proposal, test count, performance result, or implementation claim is evidence only.
  It must not be treated as current runtime behavior without fresh verification.

The active [documentation consolidation ledger](../tasks/DOCUMENTATION_CONSOLIDATION_LEDGER.md)
preserves source fingerprints and heading-level dispositions for the consolidation baseline.
